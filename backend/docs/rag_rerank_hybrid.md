# RAG: когда добавлять rerank и hybrid (BM25)

## После внедрения чанков и бюджета контекста

1. **Соберите метрики:** средний размер контекста (символы/токены), latency retrieval vs generation, доля ответов с явной ошибкой по фактам (ручная выборка или пользовательские репорты).
2. **Rerank (cross-encoder или лёгкая модель):** имеет смысл, если при росте базы чанков **precision@k** падает: в LLM попадают «почти релевантные» чанки. Начните с **rerank top 20 → top 5** после векторного поиска.
3. **Hybrid (BM25 + вектор):** полезен для **точных совпадений** (артикулы, имена, коды), которые семантика может промахнуть. Требует индекса полнотекстового поиска (PostgreSQL `tsvector` / OpenSearch) — отдельная миграция и веса fusion.

## Рекомендация

Сначала стабилизировать **чанки + бюджет + мониторинг**; затем A/B или офлайн-оценка на 50–100 запросов перед добавлением rerank/hybrid.
