# Local development with Docker Compose

Full local stack: **PostgreSQL**, **Redis**, **backend** (FastAPI), **frontend** (Next.js) with hot-reload.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) Engine 20+
- **Docker Compose v2** (recommended): `sudo apt install docker-compose-v2`
- Legacy `docker-compose` v1 works with a workaround in scripts, but may fail on Docker 28+ — prefer v2
- OpenAI API key

## Quick start

```bash
# 1. One-time setup (creates local env files, starts DB, runs migrations)
chmod +x scripts/dev-setup.sh scripts/dev-up.sh scripts/dev-down.sh
./scripts/dev-setup.sh

# 2. Set your OpenAI key in backend/.env
#    OPENAI_API_KEY=sk-...

# 3. Start the stack
./scripts/dev-up.sh
```

## URLs

| Service   | URL |
|-----------|-----|
| Frontend  | http://localhost:3000 |
| Admin login | http://localhost:3000/admin/login |
| API       | http://localhost:8000 |
| Swagger   | http://localhost:8000/docs |
| Health    | http://localhost:8000/health |

With `DEBUG=true` in `backend/.env`, the admin panel works without JWT login.

## Commands

```bash
# Start (foreground, rebuild images if needed)
./scripts/dev-up.sh

# Start detached
./scripts/dev-up.sh -d

# Stop
./scripts/dev-down.sh

# Stop and remove database volumes (full reset)
./scripts/dev-down.sh --volumes

# Re-run migrations only
docker compose --profile setup run --rm migrate
# or: docker-compose --profile setup run --rm migrate
```

## Files: committed vs local

**In git (templates):**

- `docker-compose.yml`
- `.env.docker.example`
- `backend/.env.example`
- `frontend/.env.local.example`
- `docker/Dockerfile.*.dev`

**Not in git (created on your machine):**

- `.env` — Compose / Postgres credentials
- `backend/.env` — backend secrets and config
- `frontend/.env.local` — public API URLs for the browser
- `docker-compose.override.yml` — optional local overrides
- Docker volumes `postgres_data`, `redis_data`

Never commit real `.env` files. Templates use `.example` suffix and are safe to commit.

## First-time env setup

`dev-setup.sh` copies:

```text
.env.docker.example  →  .env
backend/.env.example →  backend/.env
frontend/.env.local.example → frontend/.env.local
```

Edit `backend/.env`:

- `OPENAI_API_KEY` — required for chat
- `SECRET_ENCRYPTION_KEY` — auto-generated by setup if Python/cryptography is available

`frontend/.env.local` must use **localhost** URLs (`http://localhost:8000`), because the browser runs on your host, not inside the frontend container.

## Limitations (local dev)

- **RAG / file uploads** — need Cloudinary or S3 credentials in `backend/.env`; chat works without them
- **Email OTP login** — needs `RESEND_API_KEY`; use `DEBUG=true` for admin access without OTP
- **Webhooks** (Telegram, Instagram, etc.) — require a public URL; not available on localhost

## Troubleshooting

**`KeyError: 'ContainerConfig'` when running `./scripts/dev-up.sh`**

This happens with **docker-compose v1.29 + Docker Engine 28+** when Compose tries to recreate containers.

1. **Recommended:** install Compose v2 and use it:
   ```bash
   sudo apt install docker-compose-v2
   docker compose version
   ./scripts/dev-up.sh
   ```
2. **Quick fix** (scripts apply this automatically for v1): remove stale containers and restart:
   ```bash
   docker-compose rm -f -s backend frontend
   ./scripts/dev-up.sh
   ```
3. **Full reset** (keeps DB unless you add `--volumes`):
   ```bash
   ./scripts/dev-down.sh
   ./scripts/dev-up.sh
   ```

**Backend fails to connect to Postgres**

- Ensure `DATABASE_URL` in `backend/.env` uses host `postgres` and `?sslmode=disable`
- Run `./scripts/dev-setup.sh` again after Postgres is up

**Port already in use**

- Change host ports in `docker-compose.override.yml` (gitignored), e.g. `"8001:8000"`

**Reset database**

```bash
./scripts/dev-down.sh --volumes
./scripts/dev-setup.sh
```

**View logs**

```bash
docker compose logs -f backend
docker compose logs -f frontend
# legacy v1: docker-compose logs -f backend
```
